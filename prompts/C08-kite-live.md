# C08 · Kite live: collector, bar builder, live runner, WebSocket
effort: med · deps: C06, C07 · reads: `docs/spec/05-backend.md` (Collector and live runner, WS) · `docs/spec/08-kite-verified.md` · `docs/spec/02-data-time.md` (finalization, revisions) · D14 D20 D21
pine: — · tools: bash (`make test`, `make demo`) · browser canvas · create/edit · **no live Kite connection by you** (needs market hours and my login); tests build their own packets and use a local fake WS server.
**If short:** 1 packets + bar builder · 2 collector (ticks, backfill, reconcile) · 3 live runner + WS · 4 UI banner/live mode · 5 demo replay.

**Goal.** A live pipeline that survives restarts: ticks → 1m bars → engines → WebSocket → chart. Verified without Kite through a demo replay.

**Do**
1. `collector/packets.py` (pure): split frames (count + length-prefixed packets), parse LTP/quote/full for index and non-index per 08 (sizes and offsets from 08), prices ÷100 (currency ÷1e7), ignore 1-byte heartbeats but note liveness. Tests build packets with `struct.pack` from the documented layout (offsets written in the test, independent of the parser); a short or malformed packet ⇒ `BAD_DATA`, never a crash.
2. `collector/ws.py` (`websockets`): URL with credentials from the token store (redact in logs); subscribe/mode JSON; ≤3,000 instruments per connection; reconnect with backoff + jitter; `AUTH_EXPIRED` ⇒ stop, publish status, no retry storm. Test against a local fake server.
3. `collector/bars.py`: tick → 1m bar by **exchange timestamp** (IST → UTC); volume = delta of the day's traded volume when present, none for the index ⇒ `volume_kind=absent`; tolerate out-of-order and duplicate ticks; provisional bars at most every 250 ms; finalize at the minute rollover from tick time (not the wall clock); silence watchdog ⇒ `stale`. Use the WS mode whose index packet carries an exchange timestamp (per 08); otherwise add quality flag `received_time_basis`. Tests: rollover, out-of-order, volume-delta reset on a new day, silence.
4. `collector/service.py` (`python -m nifty.collector`; compose profile `live`; `make live`): subscribe NIFTY 50 and the front-month future (proxy volume); batched inserts into `ticks` (Alembic; hypertable, compression after 7 days; columns `instrument_id, ts_exchange, ts_received, ltp, volume_traded, oi, bid, ask, bid_qty, ask_qty`, depth only in `full`); bars upsert DB-first, then Redis pub/sub (best effort); `collector/status` API (connected, last-tick age, instruments, reconnects, stale). On reconnect backfill the gap from historical 1m (C07). After 15:35 IST reconcile the day: differences become `revision+1` with `reconciled`.
5. `engines/live.py` (runs inside the collector): feeds finalized 1m bars (and resampled buckets) to each enabled engine; persists plots/events/overlay_elements with `source_id="live"`; publishes on Redis; provisional bars go through `on_provisional` and are flagged. Restart: `restore(snapshot)`, else replay the warm-up window (D14). Property test: kill/restart mid-day ⇒ outputs identical to the batch run on the same bars.
6. `/ws/v1/stream` (cookie auth; close 1008 without it): client sends `{op:"subscribe", instrument, timeframe, engines, cursor}`; server sends `snapshot` first (recent bars + engine outputs since the cursor), then `bar`, `event`, `status`, `panel`. Live updates arrive via Redis; **if Redis is down fall back to polling the DB every 1 s**. Resubscribing with a cursor never duplicates. Bounded per-client queue: drop provisional updates first, disconnect a slow client.
7. UI: WS client with backoff and cursor resubscribe; banner for connected / stale / Kite `AUTH_EXPIRED` (link "Connect Kite"); a Live | History toggle on Chart; provisional candles drawn hollow/dashed.
8. `demo-replay` (CLI + `make demo SPEED=`): replays the oracle sessions as ticks at `--speed N` into the same pipeline under instrument `demo:NIFTY 50` (provider csv; never mixed with Kite data; hidden from the instrument list when it has no data).

**Acceptance.** `make check` green. `make demo SPEED=200`, then in the browser canvas: Live mode on `demo:NIFTY 50` shows bars arriving, NVS markers appear when signals occur, the banner turns `stale` after the demo stops and recovers when it resumes, and a reload resumes without duplicate bars. Live Kite is user-only: after market open set `MARKET_DATA_PROVIDER=kite`, connect Kite, `make live`, then check Settings → collector status.
**Record in STATE:** WS message schema, collector/runner entry points, Redis channels, ticks columns, demo instrument id.
